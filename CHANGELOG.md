# Changelog

What changed in the toolkit that a work built on it (a submodule such as InterstellarBoardGame) can notice. Newest first, one dated section per day.

Every entry ends with `Work action:` saying what a work has to do after taking the change: `none`, or the step (a command, a file to edit). The works' automatic submodule update copies these lines into its pull request, so write them for someone who has not read the toolkit's pull request. Decisions and their reasons stay in `docs/decisions.md`; this file lists changes.

## 2026-11-13

- `capture.mjs` no longer sleeps for fixed times: after a step, a resize or a reload it waits until the seat's screen is still (a catalogue's `at` and `patch` lose their `wait`); `--check`, `--png` and the page are made in one pass over the screens (they may be combined); new flags `--only <screens>`, `--step-timeout <s>` and `--timeout <s>` (a stop names the screen and step, exit 1, or 2 for the whole-run cap); a step or screen with `wait` still sleeps that long. Work action: none; drop `{ wait: ms }` steps that only waited for the screen to draw (keep those that wait for a timer in the game).
- `capture.mjs --check` can verify that the action to press now is on screen: a `catalogue()` screen takes a fifth item, a list of selectors, and each that is missing, past the viewport, or covered or cut off is reported as `unreachable` (the overflow check skips what is scrolled out of view, so it missed a cut-off button). Work action: none; to use it, add the list to the screens whose action matters (see docs/screen-preview.md).
- The footer's upper row says the screen's state in one sentence (`FooterActions place="status"`; strings `status.waitOthers`, `status.theirTurn`, `status.fillSettings`, `status.allNext`, `status.anyoneNext`, `status.pickGame` and `status.timeLeft`, which the handout's clock now uses: 残り 4:55); a pressed next button is outlined with a dark 2px edge and a tick instead of red; `--color-undo` is removed and `--color-danger` added with `Button variant="danger"` (a danger button is never the last of the main row). Work action: replace `--color-undo` with `--color-danger` in the work's tokens if it set one; add the new `status.*` keys to the work's `fonts.config.json` ui sources only if it overrides them, and run `sh toolkit/scripts/subset-fonts.sh .`; in the work's own game screens, put a `FooterActions place="status"` line where a button is greyed or pressed (such as "相手の番です") and move any red button that is last in the main row.
- Fixes from the overflow check on the numbered screens: the handout's tab bar fits a portrait phone (tabs have less padding), the band's phase pill is 16px with less padding so a game name like インディアン・ポーカー fits, and the sheet's dimmed scrim carries `data-overflow-ok` (it reaches past its section on purpose). Work action: none.
- The phase list's entries are cards; `CastView` and `EmptyView` show the flow under their content (`FlowStrip`, fed by `FlowApp`); `Sheet` floats over a dimmed screen; vertical scrolling areas take the `scroll` class (a thin, quiet scrollbar, token `--color-scroll`), and `--color-scrim` dims the screen behind a sheet; on an upright phone the top band's phase label sits in the HUD's row (`startFlow` sets `data-band-row` on the root). Work action: none is required (`--color-scroll` and `--color-scrim` fall back to neutral greys; add them to the work's `theme.css` to match its palette); a custom shell that copies `FlowApp` calls `provideFlow` (from `flowContext`) to show the flow in the screens.
- `tools/screen-preview/catalogue.mjs` gives a work what it needs to keep a numbered list of all its screens (`catalogue()` checks that screens are numbered 01, 02, … without a gap, `PARTS` is the toolkit screens' numbered parts, `flowSteps()` puts the game in a phase, `NEXT`, `btn`, `PHASE`, `MAIN` and `SCROLL` find things by the `data-uzu-*` marks); capture.mjs gains the step `{ reload: true }` (already in the toolkit) and its page keeps each large font once. Work action: none; to keep a catalogue, add a `shots.mjs` built with `catalogue()` (see docs/screen-preview.md, "Catalogue of a work") and run it with `capture.mjs --config`.
- The playing-card deck's corner index is a quarter of the card's width (it was a third), so the pips and court figures are larger. Work action: set `PlayingCard`'s `width` to 4 or more wherever the work draws it, which keeps the index at 16px.
- `HandoutReviewView` opens with the read-through's post-game greeting (`review.heading`), and the court cards (J, Q, K) lose Kennard's blue panel outline. Work action: none.
- The footer's main row is now the lower one, with bigger buttons; the cast screen's ready button and the handout's done button are both `button.next` and toggle (red-outlined when on, tap again to take back); the handout band shows no done checks; `Button` takes `on`; theme gains `--color-undo`. The strings `button.ready`, `button.unready`, `handout.done`, `handout.unready`, `button.nextLine` and `hint.readThenTap` are removed, and `handout.extend` now reads 2分延長希望. Work action: set `--color-undo` in the work's tokens if its look needs another red; remove the removed keys from `fonts.config.json` and any `strings` override, and run `sh toolkit/scripts/subset-fonts.sh .`.
- Font subsets are built from a `fonts.config.json` in each project (sample or work) instead of a script's hard-coded lists, and `scripts/subset-fonts.sh [projectDir]` builds from it (`npm run fonts` rebuilds every sample). `tools/fonts/fonts.mjs` exports `missingGlyphs(projectDir)`, which a test calls to fail when a subset lacks a glyph the project shows. Work action: add `fonts.config.json` to the work (format in the header of `tools/fonts/fonts.mjs`), add a test that calls `missingGlyphs`, and run `sh toolkit/scripts/subset-fonts.sh .` whenever that test fails (after a toolkit change in `strings.json`, for one).
- `startFlow` takes `shell` (the frame around the phases) and `strings` (any key of `packages/reader/src/strings.json`); `game`, `band`, `sendAction`, `footerSlots`, `sceneIn`, `sceneOut`, `FlowApp`, `Frame`, `TopBand`, `FooterActions`, `PhaseList` and `Sheet` are exported from `@uzu-toolkit/reader`, and `handoutScreen(handouts, props)` and `castScreen(props)` return a phase's view with its wiring. Work action: none is required; to use them, spread `handoutScreen(...)` and `castScreen(...)` in `src/main.ts` in place of `handoutKeep`, `handoutDone`, `handoutReopen`, `readyDone` and the two views, and list any `strings` override as a ui source in `fonts.config.json`.
- The dev harness's tap-next and the screen preview's `next`, `scroll` and phase name find screens by `data-uzu-actions="main"`, `data-uzu-phase` and `data-uzu-scroll` (set by the default screens, `FooterActions` included) instead of `footer .act button`, `.chat` and `header .phase`. Work action: if the work has its own preview config or a custom shell or screen, use those marks in place of the old selectors; with the default screens, none.
- The top band caps a long phase name with an ellipsis so the players stay on screen. Work action: none.
